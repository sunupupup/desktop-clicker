# 桌面区域点击器

Windows 桌面区域点击行为测试工具，使用 Python 标准库和 Tkinter。

## 启动

```powershell
python -m src.clicktrace
```

## 使用

1. 选择矩形或椭圆，设置大小、随机点击数、种子、间隔和可选的双击簇策略。
2. 点击“新增区域”会在主屏错开显示一个半透明浮层，初始为非活跃；可继续创建更多区域。表单间隔默认用于新区域；点击“同步间隔到全部区域”可立即应用到已有区域的剩余计划，区域列表会显示每块区域当前间隔。
3. 区域非活跃时，拖动浮层主体可移动；拖动右下角手柄可调整宽高。尺寸会同步到该区域设置，并让剩余点击坐标适配新尺寸。
4. 在区域列表中选中一项，可单独激活、暂停或删除；“删除全部区域”会删除所有浮层。删除区域会停止该区域计划，但保留点击记录。
5. 切换为“活跃”后，程序不调用 Windows 真实鼠标输入 API，也不激活目标窗口。命中网易 MuMu 模拟器时，按桌面区域坐标映射到对应 Android 实例；若该实例尚未连接，会通过其独立的本机 ADB 端口自动连接，再注入 Android 触摸点击。不会移动 Windows 光标或切换 Windows 前台窗口。其他窗口优先用 Windows UI Automation，无法识别为可访问控件时才回退到 `PostMessage`。每个区域使用独立后台 worker。暂停后可继续拖动或缩放，再次激活会继续剩余点击。
6. 计划完成后区域自动变为非活跃。形状、尺寸和点击策略用于新建区域；同步间隔按钮会更新已有区域的后续间隔。

输入调用记录可导出为 JSON 或 CSV。记录同时包含计划触发时间、调用/投递时间和调度延迟，便于确认程序是否按 1–2 秒排程。记录不代表网页处理已完成：UI Automation 记录的是控件调用返回，`PostMessage` 记录的只是消息入队；标有 `*` 的消息投递没有目标响应确认。MuMu 的 `Android 触摸` 记录表示 ADB 触摸注入命令成功返回。事件坐标是 Windows 桌面绝对坐标；元数据包含形状、区域尺寸和生成设置。

## 限制

- 只支持 Windows；区域必须能完整放在当前虚拟桌面内。
- 不调用 `SendInput`、`mouse_event` 或 `SetCursorPos`，不通过 `SetForegroundWindow` 激活目标窗口。MuMu 点击会在 Android 虚拟设备内部产生触摸事件，因此 Android/网页控件可能获得自身的应用内焦点，但 Windows 前台窗口与系统鼠标保持不动。MuMu 的 ADB 连接不可用、目标点在模拟器画面外或显示坐标无法读取时，该区域会暂停且不会回退发送窗口鼠标消息。
- UI Automation 只能触发目标应用公开的可访问控件；画布、游戏、自绘控件等没有对应输入后端时会回退到窗口消息，应用仍可能忽略。
- 日志区分计划时间、调用/投递时间和延迟；窗口消息投递不保证目标程序实际处理或完成了操作。无鼠标模式下，UIA 能力取决于目标应用公开的可访问控件；普通窗口消息不是通用的鼠标点击替代品。
